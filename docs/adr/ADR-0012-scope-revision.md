# ADR-0012：交付范围修订——数据输入通道纳入正式功能，数字人口播视频裁撤

日期：2026-08-26　状态：已拍板（用户决策）　取代/修订：spec §Out-of-scope 第 75 行、ADR-0008 视频部分、验收场景 3 的"视频"表述

## 背景

设计稿（2026-08-24）曾将「批量爬虫抓网」列为 Out-of-scope（素材人工筛选），口播场景要求 5 分钟内产出**数字人视频**。原型迭代中出现两个新事实：

1. 用户明确提出「出个按现在这个样子的爬取功能或者自己上传的功能」，并选定 **A+B 双通道方案**（Web 上传 + Commons/Openverse 爬虫，均可在前端操作）；
2. 项目进入 W4 收尾期，用户明确表示「不用数字人视频」——粤语讲解以**音频**（CosyVoice 三音色）为准即可满足演示与答辩需要。

## 决策

1. **数据输入从"人工放文件"升级为一等公民功能链路**：
   - Web 上传 `/upload`（license/source_url 版权红线必填校验 + 自动 pid + 后台单张入库）
   - CLI 与 Web 批量抓取 `crawl`（来源适配器架构：commons 默认 + openverse，许可白名单 PD/CC0 内置于爬虫）
   - 抓取→`ingest --pid`(逗号批量)→评审 `/review` 全链闭环
   - 原 `scripts/fetch_commons.py` 手工脚本保留但不再是主路径
2. **数字人口播视频（SadTalker 口型）降级为可选实验脚本**，交付物中的"可听"指音频；`scripts/make_talking_head.py` 不列入打包冒烟范围。ADR-0008 中 SadTalker 选型结论仍有效，仅交付层不做。
3. 验收场景 3 相应修订为：音频生成 ≤5 分钟且可播放 + RAGAS 阈值达标（已达成：0.888/0.858/1.0）。

## 理由

- 用户是唯一产品owner，其验收意愿优先于早期 spec 猜测；
- 爬虫版权红线自动过滤（PD/CC0 白名单）+ 合规 UA 已落地测试通过，风险可控；
- 数字人视频单张 13 分钟的预处理成本对演示价值有限，裁撤可将最后工期集中到包装件。

## 后果

- README/spec 对应段落同步更新；测试基线随新功能增至 245 个
- 多来源适配器约定见 `app/ingest/sources.py`：新增站点只需实现同签名函数+注册+前端 option 一行
